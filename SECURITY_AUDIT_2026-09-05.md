# Security and data-handling code audit — 5 Sep 2026

Read-only audit of the shipped code (site/, worker.js, supabase/migrations, supabase/functions, the AI proxy repo, the Teams bot) plus live checks against the production database (pg_policies, triggers) and the served headers. Purpose: know what is actually built before the Data Security white paper (SL-WP-0003) is rewritten and before the Enterprise security builds are ordered. Three audit passes (auth/tenancy, AI data path, custody/storage/egress) are reproduced in full below; the reconciled findings come first.

## Reconciled findings, by severity

### Critical — fix before anything else, and before any paper claims

1. **Cross-tenant membership hole (live).** RLS policy `ws_members_self_join` on `public.workspace_members` is `INSERT … WITH CHECK (auth.uid() = user_id)` with no other condition and no trigger. Any signed-in user who knows a workspace id can insert themselves into that workspace at any role, including owner, and then read every project in it. Verified live in `pg_policies` (5 Sep). Fix: restrict self-join to a workspace the caller owns (`workspaces.owner_id = auth.uid()`, i.e. creation only); every other join goes through `accept_invitation`. Also add `WITH CHECK` to `ws_members_admin_update` so an admin cannot promote to owner.
2. **MFA is switched off.** `site/index.html:4007` sets `window.SL_MFA_REQUIRED = false`; `auth_gate.js:831` reads it. Enforcement is client-side and fails open; nothing server-side requires AAL2; the desktop path lifts the gate before MFA runs. SECURITY_HARDENING_RUNBOOK.md and SL-WP-0003 §14 say MFA is enforced for every account.
3. **ITAR fences that do not hold.** (a) `crdt_sync.js:59` and `presence.js:38` read `window.projectConfig`, which is never assigned (`projectConfig` is a bare `let`), so collaborative sync and presence run on ITAR projects — the file header says they never do. (b) Manual Save-to-cloud and Create Revision (`helpers_modules.js:8380`, `:8083`) upload an ITAR project, including full source-document text and images, to hosted Supabase; only the background autosave is fenced (`cloud_sync.js:189`). (c) The integrity-notification sender (`notify_agents.js`) has no ITAR check and sends project name, tree and node names to Microsoft/Resend. (d) The controlled-document guard runs only on the ANEM chat/batch path (`ai_assistant.js:12214-12225`); the classic lanes (system FHA/FCIM, PRA/ZSA/CMA/FMEA, FTA, HF, reports) call `Provider.complete` directly and include controlled documents in prompts. (e) Choosing "ITAR cloud" as the AI backend does not set the ITAR header — only the project toggle or the licence flag does (`core_modules.js:276,309`).
4. **Security headers missing on part of the app.** `worker.js` stamps CSP/HSTS/X-Frame-Options only inside `serveHtml`; `/app/index.html` and any unknown `/app/<path>` fall through the SPA fallback with HTTP 200 and no headers. Verified live 5 Sep: `/app/` carries the CSP, `/app/index.html` and `/app/nonexistent-page` carry none.
5. **Sealed baselines are largely hollow in the web build.** `lock_seal.js:91` reads the stores through `(0, eval)(…)`; the production CSP has no `'unsafe-eval'` (the repo's own comments record that eval is blocked in production), so the FHA, requirements, CCA tables, items and FMEA contribute `null` to the seal and INV-19 cannot detect edits to them. Only bare-identifier stores (`ftaPages`, `systemsData`, `projectConfig.*`) are sealed. Same pattern in `stale_watch.js:53` and `lane_trees.js:75,87`.
6. **The trust page says customer content may be used to train models** (`site/trust.html:164`), contradicting the EULA ("does not use your Customer Data to train"), the same page's sub-processor line, SL-WP-0003 §6 and `tests/regression_no_training_guarantee.test.js`.

### High

7. **No AI-call or workspace audit record is written.** `public.audit_log` (hash-chain trigger, append-only revokes) and `public.workspace_audit` (member read policy) have no writer anywhere — not the app, not the proxy, not the edge functions. `audit_log` has 0 rows. `ai_usage` likewise. The only AI-call log is `projectConfig.aiAuditLog` inside the customer's own project file. SL-WP-0003 §12 and trust.html:70/91 claim otherwise.
8. **Credentials in plaintext localStorage:** the Pro+ licence bearer token (`safetyLab.license.token`), BYO Anthropic/Voyage keys, Jama username and password (`safetyLab.jama.config.v1`), live-bridge token, local-LLM key. The BYO path sends the customer's key straight from the browser to api.anthropic.com with `anthropic-dangerous-direct-browser-access`.
9. **Erasure is narrower than described.** `erase_project` is granted only to service_role (not self-service); `erase_my_account` returns a certificate id and manifest hash shown once in a modal and never persisted client-side; nothing clears the local autosave, ring, last-good, disk `.sl`, AI memory or CRDT IndexedDB copies; the manifest counts three things while the cascade removes many more. `ai_org_cache` rows are keyed by hash with no project link, so a project's cached AI answers survive its erasure (they are per-user, owner-only RLS — verified live — not org-wide).
10. **Notification edge functions accept any bearer string ≥ 16 chars** (`notify-signin`, `notify-signup`, `notify-expiry`, `notify-review`), so `notification_log` rows can be injected by anyone with the function URL.
11. **Proxy details:** the rate limit fails open on KV error; the raw licence token is written into KV keys; `x-safetylab-feature` is never read; error strings go to Workers Logs (observability on); CORS is `*`. No bodies are logged — that claim holds.
12. **Migration drift.** Production objects with no DDL in the repo: `users`, `workspaces`, `projects`, `project_documents`, `audit_log`, `license_tokens`, `approved_tenants` (exists live with an admin-only policy; the sign-in hook is unverified), `ai_org_cache`, `destruction_certificates`, `pending_comps`, the `private.erase_*` bodies, `private.audit_immutable`. `20260831_version_monotonic_guard.sql` is marked not yet applied; 0007 config-management tables are not deployed.
13. **Stale artefacts shipped in the app directory:** two `site/.fuse_hidden*` copies of older builds (919 KB, 354 KB), `site/MS_SSO_SETUP.md`, and the stale proxy copy `safety-lab-proxy_worker_SEC.js` in the deploy repo (the real proxy lives in safety-lab-proxy-deploy and does have the `/v1/ai/notify/*` routes and the sovereign router).
14. **SSO** is behind `SL_MS_SSO_ENABLED`, which nothing sets; `ms_sso.js` records the Azure provider as never enabled.

### What IS built and holds (evidence in the passes below)

RLS on every content table with the role-graded helpers in the `private` schema; invitation redemption server-side (email match, single use, 14-day expiry, no downgrade); the sign-off chain in Postgres with `verify_signoff_chain()`; the document-loss guard and 50+10 version pruning trigger; project archive with admin-only restore; the idle sign-out (web only); password-recovery forcing a new password; the content-stateless proxy that never forwards ITAR traffic to public Anthropic (503 until a sovereign backend is configured; sovereign router built for Bedrock GovCloud/Claude and Azure Gov, unprovisioned); the CSP on the main app document (no `unsafe-eval`); security.txt; the hash-chained project journal, holder-owned locks, PR-scoped reopen, cascade stamping and replay verification — all real, all browser-side over the project file; evidence packages with per-section hashes (no raw documents, no AI output text, but verbatim citation quotes from uploaded documents).

### How AI data actually moves (for the paper)

- A prompt carries: standards preamble and cert basis; the golden-thread rows in scope; the WHOLE text of every uploaded source document (or the chapters the spec index selects), all tables, image captions, under the file name; the project's own rows as exemplars; up to 24 lines of drafted-vs-edited diffs from this browser's AI memory (skipped on ITAR projects); base64 diagram images when attached; the first 300 characters of the user message also go to the corpus search endpoint. Not sent: user name/email, project UUID. No PII or secret scrubbing exists.
- Public path: browser → api.safetylabaero.com (licence check, rate limit, token count) → Anthropic verbatim → back. Nothing persisted by the gateway. Embeddings (Voyage) exist in the transport but only the connection test calls them.
- ITAR path: licence `itar_required` or header `x-safetylab-itar: 1` (project toggle) → refuse 503 unless Bedrock GovCloud / Azure Gov secrets are set; never public. Not provisioned.
- Local path: OpenAI-compatible endpoint from localStorage; same prompt content; still leaves the browser: corpus search, remote draft cache (Supabase `ai_org_cache`, response text), autosave, notifications — unless the ITAR flag fences each (it fences corpus, memory, autosave; not the cache, not notify, not manual save).
- Stored after a call: provenance fields and comments on rows; `projectConfig.aiAuditLog` (500 cap), `aiProvenance`, `aiDrafts`, `aiEvidenceRecords` (includes the model's result text); the AI assumptions ledger with citation quotes; AiMemory IndexedDB diffs; local draft cache (response text keyed by prompt hash); remote `ai_org_cache`; eval exports on download.
